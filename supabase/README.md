# Disposable demonstration environment

Local-only Supabase project `ship-safe-demo` with synthetic data.

- `config.toml`: generated by Supabase CLI 2.122.1, trimmed to Postgres, Auth, PostgREST and the API gateway. Public signups are off; synthetic users come only from the admin API.
- `migrations/20261105000000_invoices_owner_read.sql`: `public.invoices (id, owner_id, fixture_marker, ...)`, explicit SELECT grants for `anon` and `authenticated`, RLS enabled, and the owner-only policy `invoices_owner_select`.
- `lab/permissive-select.sql`: **deliberately broken** policy. It is not a migration. Only the integration harness applies it, and only inside a separate throwaway instance (`ship-safe-lab-*`) that is destroyed afterwards. Never apply it to a stack you keep, to remote staging, or to production.

Lifecycle (from the repository root):

```bash
pnpm stack:up
```

```bash
pnpm fixture:provision
```

```bash
pnpm stack:reset
```

```bash
pnpm stack:down
```

`stack:down` uses `--no-backup` and deletes local data. `scripts/stack.mjs` refuses to run in a directory linked to a hosted project, and keeps `supabase start` key output out of logs.
