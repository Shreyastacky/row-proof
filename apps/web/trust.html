Trust

You shouldn’t have to take a security tool’s word for anything.

So here is what Pyx touches, every request it sends, how to check a result without us, and where the code lives. Where something isn’t in place yet, it says so.

What it touches

Production stays closed.

Your live Supabase project
Never. Pyx refuses any target that isn’t a loopback address on a disposable local stack.
Your customers’ data
Never. Tests use synthetic users and records that Pyx creates, marked synthetic-…. It refuses to change any user or row it didn’t create.
A local copy of your database
Yes. Started from your migrations on your machine or CI runner, and thrown away afterwards.
Your API routes
Only the ones a rule lists, only on a loopback origin, and only with the test user’s own token. Supabase keys never leave the Supabase origin.
Our servers
Nothing. The CLI has no account, no telemetry and no phone-home. Results are files you choose where to write.
Credentials
Read from a file you pass with --credentials, kept out of the process environment, and never written to any output. Every result, report and ledger is scanned for them before it is written.

Check it yourself

Don’t trust the report. Check the result.

Every report comes with the raw result file. Open it in the result verifier: it recounts every check in your browser, flags a file whose stated verdict doesn’t match its own checks, and compares two releases cell by cell. It uses the same comparison code as the CLI, and the page can’t send anything anywhere.

Each result also records the exact approved rule it ran (a SHA-256 content hash) and the commit it ran against, so a result can’t silently be swapped for a run of a weaker rule.

Measured

What it catches, and what it misses.

We seed real access bugs into a throwaway Supabase project and publish the result of every run, including the miss: see the benchmark and its full table.

A broken test setup never turns green. Expired tokens, two “users” who are the same account, a test record deleted mid-run, an anonymous request that Auth accepts as a user, or an unreachable stack all end as blocked, never as a pass.

Who decides

The rule is approved by a person, not by the pull request.

The person responsible for the data approves an exact version of each rule, identified by its content hash. CI reads the approved rule from your protected branch, so a pull request that weakens the rule and the code at the same time still gets checked against the old, stricter rule. Promotions record a digest of the approval itself, so editing who approved it afterwards is detected.

Today approvals are local and self-attested: anyone who can write to the approval store can change it. Protect that folder with code owners and branch protection.

Source and supply chain

Read every line.

  • Source available. The full source is on GitHub under FSL-1.1. Each release becomes Apache-2.0 two years after it ships.
  • Pinned dependencies. Frozen lockfile installs, a seven-day minimum age for new package versions, and GitHub Actions pinned to exact commits.
  • Signed releases. The release workflow publishes to npm with provenance, so npm audit signatures can confirm a package was built from this repository by that workflow. This starts with the first public release.
  • Tested against the real thing. Over 250 unit tests, plus 33 scenarios against a real local Supabase stack, are part of the CI workflow.

Report a problem

Found something? Tell us.

Email us with a minimal, redacted reproduction. Please don’t send credentials or real records. The policy is in SECURITY.md, and the contact is also published at /.well-known/security.txt.

Pyx has not had an independent security review yet. When it does, the report will be linked here.

What a pass means

A pass is narrow, on purpose.

It means the approved checks held on the named stack, at the stated time, through the listed request paths. It is not a penetration test, a certification, or a statement about production or anything the rules don’t list. Writes, list queries, team membership, storage and edge functions are not checked automatically yet.
